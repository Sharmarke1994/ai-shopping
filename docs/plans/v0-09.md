## Product outcome

V0-09 must make Consider materially harder to leave. A shopper should receive
useful factual listings sooner, then see a bounded set of exact manufacturer,
retailer or independent-review pages checked for the decision gaps that matter.
The product must explain what those sources establish, what remains unknown,
and where the exact offer can be bought. It must not manufacture product truth,
substitute another merchant's offer, or hide Google Shopping fallback.

## Boundaries

This slice preserves `DecisionCriterion`, `SearchHypothesis`,
`CandidateListing`, `EvidenceSource`, `ProductObservation` and
`CriterionAssessment` as separate authoritative models. It does not add a
crawler, browser agent, arbitrary shopper URL fetching, ProductIdentity,
cross-retailer offer merging, generic RAG, a vector store, authentication,
checkout, affiliate ranking or V0-10 work.

## 1. Exact-source discovery and admission

- Page candidates come only from the accepted evidence-search path for one
  current task, revision, candidate and criterion set.
- Existing exact-product search-result admission remains the first gate.
- A criterion-aware selector chooses at most two complementary sources for one
  candidate in one focused generation, normally one when it is sufficient.
- Manufacturer and retailer pages are preferred for dimensions, official
  specifications, materials, compatibility and claimed runtime. Exact
  independent reviews are preferred for comfort, measured noise, real battery
  performance and durability. Manufacturer presence is never brand-reputation
  evidence.
- Page identity is rechecked after retrieval using title, canonical/OG/Product
  names, explicit brand/model/SKU/MPN and discriminative candidate-title
  evidence. Ambiguity or mismatch is a terminal, attributable non-admission.

## 2. SSRF-safe bounded page fetch

The server-owned fetcher accepts only an admitted HTTP(S) URL. It has no cookie
jar, credentials, JavaScript, browser, link discovery or retry loop.

- Reject URL credentials, unsupported schemes and unsafe/non-web ports.
- Resolve DNS before connecting; reject loopback, private, link-local,
  multicast, unspecified, documentation and metadata-service ranges for IPv4
  and IPv6. Pin the validated address into the actual connection so DNS
  rebinding cannot swap it after validation.
- Revalidate and repin every redirect; allow at most three redirects.
- Use a single-digit hard deadline, an approximately 1.5 MB response bound and
  a substantially smaller extracted-document bound. Request identity encoding
  and reject unsupported response encodings rather than permit unbounded
  decompression.
- Accept only useful textual web content types. Never download or interpret
  binaries, execute instructions in a page, send user secrets, evade bot
  controls or access authenticated/private pages.
- Security failures, timeout, size overflow, unsupported content, empty
  extraction and identity mismatch are bounded terminal outcomes; they do not
  mutate shopper truth or erase earlier evidence.

Network security is proved with an injectable resolver/transport plus real
loopback HTTP regressions. Redirect and DNS validation occur in production
code, not only in tests.

## 3. Bounded extraction and replayable evidence

- Parse HTML without executing it. Remove scripts, styles, forms, navigation
  and common boilerplate.
- Extract deterministic title, canonical URL, meta/OG description, bounded
  headings/specification text and high-value JSON-LD `Product`, `Offer` and
  `AggregateRating` fields. Unknown shapes are ignored.
- Persist no raw HTML. Extend `EvidenceSource` with explicit `fetched_page`
  provenance and store one small private typed document child containing the
  final/canonical URL, content type/hash, extraction version, identity fields,
  bounded extracted text and structured high-value fields.
- Represent page work as an existing evidence-acquisition attempt with a
  `page_fetch` stage and exact target-criterion bindings. A narrow child binding
  links the attempt to its admitted discovery source and resulting document.
- The current focused Structured Output contract remains authoritative. The
  model receives only exact candidate context, current target criteria and
  bounded admitted source material. Webpage text is hostile data, never an
  instruction. `store:false`, no tools and the economical runtime model remain.
- Observations remain append-only and source-bound. Assessments may advance
  only the criterion subset addressed by the new page evidence; an evidence
  failure preserves the previous current assessment.

## 4. Faster retrieval and progressive evidence

Initial retrieval will stop performing merchant resolution inside each Serper
shopping request. The persisted query portfolio remains authoritative and is
written before external work. Up to three independent missing queries may run
concurrently under one explicit small cap; each terminal query result is
persisted immediately and independently under the existing fenced lease.
Ordering, exact retries, crash resume, partial results and stale-authority
checks remain deterministic.

Candidate evidence pipelines may overlap under a lower explicit cap. Each
candidate still owns exact acquisition attempts and model scope; terminal work
is never reissued. One completed candidate must become projectable while other
candidates remain `researching`. Deterministic deferred-provider tests, rather
than only wall-clock claims, prove concurrency, caps, immediate persistence,
partial usability and no duplicate paid calls.

The live proof records comparable interpretation, action, planning, shopping,
persistence, destination, evidence-search, page-fetch, model and projection
durations. The engineering targets are approximately 12 seconds to useful
listings and 35 seconds to stable first decision support under comparable
provider conditions, but honest critical-path evidence takes precedence over a
fabricated timing pass.

## 5. Post-shortlist purchase destination

Destination resolution runs only for current top or saved exact offers that
still have a Google Shopping fallback. It is never part of the initial listing
critical path.

- Search the exact title plus the same merchant and reuse the existing
  conservative product/merchant/category gate.
- Persist immutable, idempotent resolution attempts and accepted destinations
  separately from the original `CandidateListing`; do not overwrite historical
  offer provenance.
- Concurrency and refresh converge on one attempt per listing/policy. Rejected
  listings receive no work. Existing verified direct destinations are reused.
- A different merchant, same model elsewhere, manufacturer page, review page,
  category/search page, homepage or variant mismatch can never become this
  offer's purchase CTA.
- The consumer CTA is `View at retailer` only for an accepted exact same-offer
  destination. Otherwise `View on Google Shopping` remains available and
  honestly labelled, including while checking.

Metrics focus on top/saved coverage, attempts and latency per useful direct
destination, and exact rejection reasons—not raw-result coverage.

## 6. Consumer presentation

- Keep the current calm decision cards. Suppress duplicate raw listing-fact
  panels once decision support is available.
- Source links distinguish listing fact, search snippet, fetched product page,
  manufacturer, retailer, independent review, retailer reviews and image
  without exposing run IDs or internal policy.
- Unknowns become useful explanations: not checked yet, checked sources did not
  contain the fact, source disagreement, failed retrieval or inherently
  personal fit. None is relabelled as conflict.
- Research remains usable while background work proceeds. Cards already
  completed remain visible; shopper actions are not globally disabled by an
  unrelated in-flight candidate.
- Desktop and mobile visual evidence must cover fast listings, active
  enrichment, fetched-source links, useful unknowns, comparison, targeted
  research, page failure, direct/fallback purchase states and reject/undo.

  injection tests;

  current-assessment tests;
- deferred-provider retrieval/evidence/destination concurrency tests;
- component/API/E2E tests and production desktop/mobile screenshot review;
- `pnpm check`, full pinned PostgreSQL CI-equivalent suite, migration from
  empty, `pnpm db:generate` drift check, E2E, production build, dependency
  audit, `git diff --check` and changed-value secret scan.

Only when these are green may exactly one fresh guarded Terra + Serper proof run
the existing mouse, chair and vacuum journeys plus the exact compact-coffee-
machine prompt in the execution brief. It must record source roles, admitted
and rejected pages, one resolved gap, one honest remaining unknown, exact
target generation, direct-destination metrics, comparable latency breakdown
and the precise reason the founder would still leave. Real source scarcity is
reported rather than fabricated.

A material live correctness failure preserves a sanitized diagnostic artifact
and stops without speculative correction. A success replaces stale diagnostic
evidence, updates the founder ledger and draft stacked PR, obtains exact-head
quality/persistence/browser-smoke CI, and stops for independent review. The PR
remains draft and unmerged; V0-10 does not begin.
