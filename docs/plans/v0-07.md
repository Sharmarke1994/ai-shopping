## Product outcome

V0-07 completes one coherent capability: selectively investigate a small
post-triage candidate pool, preserve attributable evidence, derive bounded
product observations, assess every current criterion, surface the
best-supported options, and compare exact saved listings against the current
brief. It does not create product identity, a catalogue, a crawler, a match
percentage, or a global reputation model.

## Semantic firewall

The write paths remain deliberately separate:

```text
DecisionCriterion (shopper authority)
        ↓ read only
EvidenceResearchPlan (acquisition hypothesis)
        ↓ provider output
EvidenceSource (attributable source data)
        ↓ deterministic/model extraction
ProductObservation (bounded product claim)
        ↓ revision-specific interpretation
CriterionAssessment (one candidate × one current criterion)
        ↓ deterministic comparison
Decision support (ordering, top options, saved comparison)
```

No evidence, observation, assessment, or comparison contract has a capability
to write `DecisionCriterion`. Search/evidence query text is strategy, never
truth. Model IDs and authority fields are server-owned.

## Durable records

### EvidenceResearchRun

One bounded plan for a current task revision and its current SearchRun. The
logical identity is task + SearchRun + revision + strategy version. It records
status, planned/researched candidate counts, query/model call counts, partial
failure counts, and timestamps. A retry loads the first winner.

### EvidenceAcquisitionAttempt

An immutable planned stage for one exact CandidateListing and purpose:
`organic_search`, `observation_extraction`, or `visual_extraction`. The request
fingerprint binds the candidate, source inputs, prompt/query version, and
purpose. Completed attempts are never reissued; pending attempts resume;
failures are isolated and sanitised. External calls never run inside database
transactions.

### EvidenceSource

An attributable, bounded source record scoped to task, listing SearchRun, and
exact CandidateListing. Roles are `listing`, `retailer`, `manufacturer`,
`independent_review`, `retailer_review_aggregate`, `visual`, or `other`.
Sources preserve an HTTP(S) URL or exact image/listing provenance, a bounded
title/excerpt, provider identity, observed time, and a deterministic
fingerprint. Organic search results enter candidate EvidenceSource storage only
after a deterministic server-owned title/model/category relevance gate; generic,
search/category, mismatched-model, comparison, or otherwise ambiguous results
are discarded rather than promoted by the model. Different sources are never
merged merely because their claims agree.

### ProductObservation

An observation belongs to one evidence source and one exact CandidateListing.
It may reference a task-local concept but is not a criterion or fit judgement.
Its versioned value is a closed union: boolean, money, quantity, rating
aggregate, categorical values, or bounded text. Derivation is deterministic,
source-text extraction, or visual inference. Supported and ambiguous claims
remain distinguishable. Model-derived rows preserve model and prompt version.

### CriterionAssessment

Exactly one assessment version per task + authoritative revision + listing +
active criterion. It records `meets`, `conflicts`, `uncertain`, or
`not_applicable`, a bounded qualitative relation, explanation, method/model,
and exact observation links. Old revisions are immutable history. Current UI
loads only the current revision.

## Assessment policy

- Missing evidence is `uncertain`, never `meets` or `conflicts`.
- Hard conflict requires direct, comparable, admissible evidence.
- A money ceiling is deterministic. A target reports signed distance without
  invented tolerance. A target-plus-stretch above target remains conditional.
- Wireless evidence never supports battery quality by itself.
- Retailer/manufacturer comfort marketing cannot prove personal long-session
  comfort.
- Visual observations may support shape discussion but can never create a hard
  conflict.
- Review aggregates retain rating, count, source, and exact-product
  provenance; assessment may distinguish broad sustained evidence from a high
  rating on a small sample without a universal score.
- Brand reputation requires persisted evidence. No brand whitelist or model
  latent knowledge is admissible.

Deterministic guards validate model proposals and own money/hard-conflict
semantics. Invalid model output fails closed to factual observations and
uncertain assessments.

## Selective acquisition

Research begins after existing hard triage and conservative presentation
grouping. The initial policy selects at most six representative listings using
retrieval lineage and existing direct evidence only; this is research
allocation, not suitability ranking. Normally one focused organic search is
planned per candidate, with a second only when materially different current
criteria require it. Existing structured listing fields are mapped first.

One bounded multimodal product-understanding call per candidate may return two
clearly separated sections: source-grounded observations and proposed
criterion assessments. The image and external text are untrusted data. The
call uses strict Structured Outputs, no tools, no web, no state mutation,
`store:false`, and explicit source IDs. The server independently validates and
guards each section; proposed assessments never bypass deterministic evidence
admissibility policy.

## Decision presentation

Current assessments drive a lexicographic comparator:

1. no direct hard conflict;
2. more hard-criterion support;
3. more strong-preference support;
4. more ordinary-preference support;
5. fewer decision-critical unknowns;
6. transparent money-target distance;
7. stable listing identity tie-break.

No scalar score is stored or shown. The first three to five researched options
show concise `Why it fits`, `Watchouts`, `Still unknown`, and source links.
Two to four exact saved listings can be compared in criterion rows. Comparative
copy is derived only from current persisted assessments and may decline to name
a winner when evidence is tied or inadequate.

## Refinement and reuse

A new shopper revision never rewrites evidence sources or observations.
Existing exact-listing observations may be reused to create new
revision-specific assessments. New search occurs only through the existing
V0-05 action policy. Saved listing semantics remain unchanged.

## Protected failure behaviour

- Refresh never reissues completed research stages.
- Partial research retains completed sources and observations and resumes only
  pending work.
- One source/model failure does not remove factual listing data.
- Stale authority cannot publish current assessments.
- Cross-task/run/listing/criterion references fail closed in both PostgreSQL
  constraints and validated readers.
- Prompt-injection text remains inert source data and cannot select policy,
  tools, IDs, state writes, or judgement.
